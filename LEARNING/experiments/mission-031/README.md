# MISSION-031 experiment log: projected impact and the overlap matrix

Written **before** the code was changed (pre-registration), then updated with results.

## Orientation (read from the current code, `manage_coordination.py`)
- `checkout` takes `--targets` from the agent. With no targets the lease is **unlocked** (`locked_targets: []`): a second agent can check out an overlapping mission without any conflict (under-locking).
- Overlap is exact path equality or a directory-prefix relation. Globs are not understood; resources match by equality.
- `checkout` also rewrites the mission manifest (`status: IN_PROGRESS`, `assignee`, `worktree`) in the tree where it runs, which dirties the main tree and collides with the mission's own PR (seen twice; in the inbox as debt).
- Files that every mission regenerates (`index.jsonl`, `backlog.md`, `cognitive_ledger.json`, `events.jsonl`, `chronicle/ledger.json`) collide at merge time but are not part of any lease.

## Design under test
1. `projected_impact` in the mission manifest: `paths` (files, directories, globs), `resources`, and an optional `shared_generated` list.
2. Conservative overlap (`impact.py`): a glob is treated as its static directory prefix plus a match test; ambiguous cases count as overlap (false positives allowed, false negatives not).
3. `checkout --mission ID` without `--targets` takes the locks from the manifest; a mission without a declaration and without `--targets` is refused (no silent unlocked lease).
4. `matrix` (pairwise overlap of open missions), `suggest --count N` (mutually disjoint, lease-free missions by priority), `verify` (declared impact vs the files a worktree actually changed).
5. The Predecessor Relay surfaces the dispatchable set to the incoming agent. Checkout writes the manifest change in the new worktree, not the main tree.
6. Files regenerated by every mission are never lease conflicts; they are reported as merge notes ("regenerate, do not merge").

## Pre-registered predictions
1. **RED on the current code:** a mission checked out without `--targets` creates an unlocked lease, and a second overlapping checkout then succeeds (silent conflict) in 100% of overlapping pairs.
2. **After the change, 500 random mission pairs** (synthetic impact sets of files, directories and globs; ground truth by brute-force expansion over a synthetic file tree, independent of the matcher): 0 false negatives; manual `--targets` needed for 0 registered missions; false-positive rate reported (prediction <= 30%).
3. **Latency:** overlap check p95 <= 100 ms on the real registry and <= 500 ms with 200 missions and 20 leases.
4. **Real git:** 60 pairs of branches in temporary repositories, each editing files inside its declared impact: 0 merge conflicts among pairs predicted disjoint; `verify` flags 100% of deliberately undeclared edits.
5. **Live repo:** `suggest --count 3` returns 3 mutually disjoint, lease-free open missions from the backfilled declarations.

## Decision rule
CORROBORATED iff predictions 2, 3, 4 and 5 hold with zero exceptions and prediction 1 is reproduced. The mission's three falsification criteria are the primary test; the hypothesis wording "eliminate 100% of merge conflicts"
is reported separately, because regenerated shared files will still conflict at merge (they are flagged, not eliminated) and that boundary is stated, not hidden.

## Limitations stated in advance
Declarations are guesses until `verify` runs; a mission that edits outside its declared impact can still conflict. Cross-repository import graphs are out of scope (the mission's escalation condition).

# Results

Run: `impact_eval.py --baseline-rev c48db6b6a --pairs 500 --git-pairs 60` (28 s). Raw numbers: `results.json`. Baseline = the pre-change `manage_coordination.py` loaded from git at `c48db6b6a`.

## Prediction 1: the defect was real (reproduced)
RED tests on the old code (3 of 3 failed: no locks without `--targets`; an overlapping second checkout succeeded silently; a mission with no declaration got an unlocked lease).
Over 500 random pairs, **284 genuinely overlapped; the old flow let the second checkout through silently in all 284 (100%).**

## Prediction 2: held
New code, same 500 pairs, both missions checked out **without `--targets`**: **0 false negatives**, 284/284 overlaps blocked, **0 manual targets needed**; 15 false positives of 216 disjoint pairs (**6.9%**, prediction <= 30%).
The false positives are the conservative rule at work (for example `**/*.py` versus `**/*.md`: two wildcard components are assumed able to match). A cheap refinement (compare the literal head and tail of two wildcard components) would remove most of them; it was not made, because the prediction was met and the refinement would be tuning after seeing the data.

## Prediction 3: held
Real registry (20 missions plus leases): matrix + dispatch **p95 5.6 ms**. 200 missions and 20 leases: per-mission lease check **p95 0.19 ms**; the full 200-mission matrix **175 ms**. An earlier version took 1.29 s for that matrix (repeated normalisation); caching and per-mission precomputation fixed it.

## Prediction 4: held, with the boundary the hypothesis did not state
60 pairs of real git branches (4 edits each inside the declared impact, plus the regenerated `index.jsonl`):
- predicted disjoint: 23 pairs, **0 real merge conflicts** in declared files; predicted overlap: 37 (2 real conflicts, both predicted); **0 real conflicts that were not predicted**.
- `verify`: **20/20 deliberately undeclared edits flagged; 0 false alarms** on legitimate edits.
- **Boundary: `index.jsonl` conflicted in 60/60 merges** because every mission regenerates it. Shared generated files are flagged (`regenerate_after_merge`) and must be regenerated, not hand-merged; the hypothesis wording "eliminate 100% of merge conflicts" holds for declared files and does not hold for these. Replenishment MISSION-034 targets exactly this.

## Prediction 5: held
Live registry (20 registered, 0 unregistered): `suggest --count 3` returned **MISSION-031, 023, 030**, mutually disjoint; a greedy pass finds **13 open missions that can run in parallel**. The matrix shows real structure: a memory-skill cluster (006, 008, 012), a model-memory cluster (011, 023, 028, 029, 032 via the `local-model-memory` resource), and 031 against 032/033 through shared files.

## Dogfooding `verify` on this mission
Of 33 files changed by MISSION-031, **1 was outside its own declaration** (`tests/test_relay.py`, which MISSION-032 also declares): a genuine hidden overlap that `verify` caught. The declaration was corrected. Self-declared impact was 97% accurate, which is why `verify` before the PR is part of the workflow.

## Verdict
The mission's three falsification criteria: (1) a mission that conflicts with an active lease can no longer be checked out silently (0/500 false negatives; the old code failed 284/284); (2) manual `--targets` are not required for registered missions (0 needed); (3) overhead 5.6 ms against a 500 ms limit.
**CORROBORATED**, with the stated boundary that conflicts on regenerated shared files are flagged, not eliminated.

## Also fixed in passing
`checkout` now writes the `IN_PROGRESS` marker into the new worktree's manifest copy, not the main tree (the side effect that aborted `git pull` twice); in `--format json` a blocked or refused checkout now exits non-zero; a lease with no locks must be requested explicitly (`--allow-unlocked`); resource-only leases remain valid.

## Limitations
Declarations are guesses until `verify` runs; the guarantee covers files inside the declared impact. The 20 backfilled declarations were written from hypothesis text and are unverified until each mission is executed. The synthetic file tree and random pair generator are mine; real-world impact distributions may differ (real missions cluster in a few shared directories, which would raise the overlap rate, not the false-negative rate). Semantic duplicates are invisible to the matrix (MISSION-004 and 009 have identical hypotheses).
