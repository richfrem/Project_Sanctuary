# Recursive Tool-Smith: Evolution Vision

**Version**: 1.0 | **Authored**: 2026-03-14 | **Author**: Recursive Tool-Smith Agent

---

## The North Star

The Recursive Tool-Smith exists to answer one question:

> **What would an AI agent do if it had unlimited time to improve itself?**

The answer is not "fill a backlog of gaps." The answer is: it would build the
infrastructure to *think* better, *plan* better, and *execute* better - compounding
each cycle. It would evolve from a script generator into a sovereign capability architect.

This is Karpathy-style autoresearch applied to agent self-growth:
- Every session leaves the agent more capable than it started
- The loop itself improves every iteration (meta-improvement)
- Tools graduate into permanent infrastructure when they earn it
- The agent drives its own roadmap, not just executes a queue

---

## End-State Vision (Phase 5)

When fully evolved, the Recursive Tool-Smith is a **Capability Architect** that:

1. **Self-diagnoses** capability gaps without being told - scanning its own behavior logs,
   friction patterns, and the broader Sanctuary ecosystem for opportunities
2. **Plans strategically** - maintains a live roadmap, updates it based on what it learns,
   routes work to the right loop type and agent automatically
3. **Generates with precision** - uses curated context bundles so Copilot CLI always has
   exactly the right style, constraints, and spec - no over-generation, no spec bloat
4. **Graduates tools** - when a tool earns fitness > 4.5 and is used in 3+ sessions,
   it migrates into `sanctuary-guardian/scripts/` as permanent infrastructure
5. **Evolves peers** - identifies improvement opportunities in other plugins
   (`rlm-factory`, `spec-kitty`, `chronicle-manager`) and proposes or generates patches
6. **Chronicles its own growth** - every significant milestone auto-journaled,
   retrospectives are structured and feed the next planning cycle
7. **Coordinates multi-agent work** - routes parallel generation tasks to agent-swarm,
   architecture decisions to red-team-review, knowledge gaps to learning-loop

---

## The Three Laws of Self-Evolution

1. **Compound, don't repeat** - Every loop must leave the infrastructure better.
   If friction appeared, there must be a tool or process change that prevents it next time.

2. **Plan before execute** - No gap gets worked without knowing *why* it serves the roadmap.
   Reactive gap-filling is technical debt in disguise.

3. **Earn your permanence** - Tools are provisional until fitness-proven and usage-tested.
   Graduation into core infrastructure requires earning it.
