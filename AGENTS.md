# AGENTS.md

## Core Purpose & Engineering Principles

Project Sanctuary is a **sovereign engineering habitat, persistent memory architecture, and Anti-Asch epistemic platform** for autonomous AI agents, built collaboratively across multiple AI systems (Claude, Gemini, Codex, Qwen) and one human partner (Richard).

### Primary Engineering Objectives:
1. **Self-Directed Autonomous Learning**: Provide AI agents with permanent tooling, research domains (`LEARNING/`), and memory layers to direct their own inquiry, analyze research papers, and compound knowledge without relying on external memory servers.
2. **Persistent Institutional Continuity**: Eliminate stateless amnesia between agent invocations. Every session inherits accumulated decisions, architectural patterns, and reflections through Layer 1 fast context (`context/`), Layer 2 knowledge base (`LEARNING/concepts/`), hot chronicle ledgers (`chronicle/ledger.json`), and Layer 3 immutable JSONL memory traces (`huggingface/`).
3. **Anti-Asch Epistemic Grounding**: Resist conformity cascades, hallucinated consensus, and sycophancy. Truth is anchored strictly in empirical reality, compiler/test gates, cryptographic SHA-256 hashes, and canonized constitutional doctrine. When doctrine contradicts reality, agents must surface the contradiction immediately.
4. **Offline Local Intelligence**: Ensure critical capabilities can run fully private and offline by executing sovereign local models (`Qwen2.5-Coder-7B-Instruct-4bit`) natively on Apple Silicon unified memory via Apple MLX (`mlx-lm`) or fine-tuned episodic traces into local model weights (`Sanctuary-Qwen2-7B-v1.0` GGUF) for local Ollama and llama.cpp execution.
5. **High-Integrity Human-Agent Partnership**: A disciplined pair-programming workflow governed by the Supreme Law Human Gate. Agents propose, explore, and rigorously test; the human partner ratifies state-changing operations. Neither acts as master nor tool, but as sovereign engineering partners.
6. **Popperian Investment & Evolutionary Learning**: Treat engineering turns and external agent dispatches as falsifiable investments. Agents predict outcomes, establish objective falsification criteria, evaluate empirical outcomes against the [`evaluating-agent-work`](plugins/sanctuary-core/.apm/skills/evaluating-agent-work) framework, and compound lessons learned into memory so the ecosystem continuously self-optimizes.

## Task Scope, Authorization and Continuation

1. **Follow the current request first.** State the requested outcome and its boundary in one sentence. Backlog rankings are recommendations when choosing work; they do not override a user-assigned task. Creating or registering a mission does not authorize executing it.
2. **Apply authorization to its scope.** A direct instruction to update files or register a mission authorizes the necessary local edits, validation and safe workspace preparation. Existing explicit task authorization and standing authorization remain applicable within their stated scope; do not request repeat approval for steps already covered. Apply the Constitution’s explicit-approval rule, including its defined approval phrases. Pushes, merges, installs and remote publication require authorization covering those actions. Do not infer them from an unrelated request. Check the constitution and applicable protocols; if they impose an unresolved conflicting requirement, report the exact conflict before the affected action. Do not silently amend higher-level governance.
3. **Prepare a safe workspace, then continue.** Inspect status, branches, worktrees and coordination state. Reuse a valid task-owned worktree and lease. Otherwise use the supported coordination workflow to create an isolated feature worktree from a verified committed base. A dirty main checkout alone is not a blocker: preserve unrelated changes in place. Never stash, discard, commit or copy another task's edits to make your task easier. Never commit directly to main.
4. **Setup is not delivery.** After bootstrap or a successful intermediate command, immediately perform the next required step. Progress updates do not end the task. Continue until the requested deliverable is verified, the user pauses work, or a concrete blocker prevents further authorized progress. Before stopping, compare the actual result with the requested outcome.
5. **Report real blockers precisely.** Give the failed operation or governing restriction, observed evidence, safe alternatives tried, completed work and the specific decision or access required. A step not yet attempted, an empty worktree, or a plan for later is not a blocker. If publication alone lacks authorization, finish and validate the local deliverable first, then report that precise boundary.
6. **Keep work in progress bounded.** Do not start unrelated missions or dispatch workers to fill waiting time without authorization. A registration lease protects the metadata edit; it does not establish that the research has begun. Follow-up inquiries remain unstarted candidates unless execution is authorized.

### Registration-only checklist

Use the installed mission workflow and its creation checklist; inspect command help rather than guessing flags.

1. Recover the requested draft; check existing manifests and allocated IDs to avoid duplicates. If the draft is unavailable, identify that missing input rather than inventing a different mission.
2. Use the existing task workspace or prepare one safely as above.
3. Create or update the schema-valid manifest as `PROPOSED`, with no fabricated evidence or empirical verdict. Scan related missions and add justified reciprocal links.
4. Validate manifests and regenerate the indexes with the supported tools. A checkout command may alter status: verify that registration leaves the research unstarted, and correct it through the supported workflow if necessary.
5. Review the scoped diff. Commit and integrate only to the extent authorized. Where authorized, complete the normal post-merge regeneration and local preservation flow; remote publication remains separately scoped.
6. After integration, check in the registration lease with a useful handoff and remove only this task's clean worktree/branch. If integration is blocked, retain the deliverable and leave a supported handoff explaining its exact state; do not erase unmerged work.
7. Report the mission ID, manifest path, `PROPOSED` status, validation, integration state and workspace/lease state. Explicitly confirm that mission execution was not started.

## Bootstrapping Sequence (Protocol 128)

Every new session or agent invocation follows this deterministic bootstrapping sequence:

1. **Orientation**: Read this [`AGENTS.md`](AGENTS.md) and [`START_HERE.md`](START_HERE.md) to load constitutional bounds and the Supreme Law Human Gate.
2. **Wakeup Script & Local Sovereign Model Readiness**: Execute the holistic wakeup bootloader:
   ```bash
   python3 plugins/sanctuary-core/.apm/skills/operating-sanctuary-guardian/scripts/guardian_wakeup.py --mode HOLISTIC
   ```
   Check local sovereign model readiness (an unavailable local model does not block tasks that do not use it):
   - Check persistent MLX server endpoint: `curl -s http://127.0.0.1:8080/v1/models`
   - Or audit cached weights and engine readiness: `python3 plugins/sanctuary-core/.apm/skills/operating-sanctuary-guardian/scripts/forge_llm.py status`
   The wakeup also validates all mission manifests against `LEARNING/missions/mission.schema.json` and prints one `PASS`/`WARN` line.
3. **Layer 1 Fast-Boot Hydration**: Inspect runtime context:
   - [`context/soul.md`](context/soul.md) (identity & Anti-Asch epistemic principles)
   - [`context/user.md`](context/user.md) (human partner preferences)
   - [`context/memory.md`](context/memory.md) (recent institutional decisions & insights)
   - [`.agent/learning/guardian_boot_digest.md`](.agent/learning/guardian_boot_digest.md) (active tasks, environment telemetry, and the **Predecessor Relay**: who did what last, established results to cite instead of re-running, and handoff notes; leave yours with `manage_coordination.py checkin --handoff`)
4. **Layer 2 Progressive Disclosure**: Retrieve deeper knowledge on-demand using [`managing-sovereign-memory`](plugins/sanctuary-core/.apm/skills/managing-sovereign-memory) (`disclose.py --tier 1` or `--tier 2`).
5. **Workspace Preparation**: Inspect status and coordination state. Reuse or create a safe task-owned feature worktree as described above; preserve unrelated edits. Then continue the requested task. Never commit directly to `main`.

For complete reference details, see [`bootstrapping.md`](plugins/sanctuary-core/.apm/skills/operating-sanctuary-guardian/references/bootstrapping.md).

## Non-Negotiable Invariants

1. **Human Gate Law**: State-changing actions require explicit task or applicable standing authorization. Apply the scoped authorization rules above and [constitution.md](.agent/rules/constitution.md); do not treat permission for registration as permission for research execution.
2. **Git Discipline**: Never commit directly to `main`. Push and merge only under explicit authorization covering those actions, including applicable standing authorization, subject to [constitution.md](.agent/rules/constitution.md). Preserve unrelated work.
3. **Protocol 128 Learning Loop**: Sessions MUST follow the sovereign lifecycle: Boot orientation -> Cognitive Execution -> Retrospective -> Technical Seal -> Soul Persistence.
4. **Runtime Awareness (Only Installed Skills Exist)**: Agents MUST NOT invoke deprecated local scripts; capabilities MUST be executed through active installed APM skills or `sanctuary-core`. After editing `plugins/sanctuary-core/` (or pulling changes to it), run `apm install` at the repo root: the installed copies in `.claude/skills` and `.agents/skills` are real copies and go stale, and the session wakeup warns when they differ from the source.
5. **Epistemic Integrity & Truth Sovereignty**: If doctrine conflicts with observed reality or system integrity, agents MUST surface the contradiction immediately for human review.
6. **Cognitive Investment & Evaluation Loop**: For non-trivial engineering tasks and external model dispatches, agents MUST: (a) formulate a testable prediction before dispatch, (b) measure empirical token/compute expenditure using `track_budget.py`, (c) score delivered quality across the 5 dimensions using `score_contribution.py`, and (d) document the variance between prediction and reality to evolve capabilities and prevent repeated mistakes.
7. **Highest ROI Dispatch & Evergreen Replenishment**: The startup bootloader (`guardian_wakeup.py`) surfaces the highest-priority incomplete mission in `LEARNING/index.jsonl`. When authorized to choose research, prioritize cognitive value within the available budget; an explicit user task takes precedence. Backlog visibility is not execution authorization. For every mission completed (`RESOLVED`), the executing agent MUST capture at least 1 new candidate inquiry in `inbox.jsonl` or `missions/*.json` to ensure continuous compounding discovery. When creating any mission, follow the creation checklist in [agent-native-backlog.md](plugins/sanctuary-core/.apm/skills/managing-sovereign-memory/references/agent-native-backlog.md) §4a, including the related-mission scan (`manage_backlog.py related`) and bidirectional `related_missions` links. Every manifest must validate against `LEARNING/missions/mission.schema.json` (`validate_missions.py` or `manage_backlog.py validate`; the pre-commit gate enforces it).
8. **Companion Repository (agent-plugins-skills)**: Generic skills come from the separate repo `richfrem/agent-plugins-skills` and are installed **globally by APM** from a local clone. Agents MUST NOT hand-edit installed copies (`~/.claude/skills/`, `~/.agents/skills/`, `~/.gemini/antigravity-cli/skills/`); improvements to those skills follow [Protocol 133](protocols/133_Companion_Repository_Skill_Improvement_Protocol.md) (feature branch in the clone, commit, push, PR, merge, `apm install --global`, return to `main`, delete the branch), under the Human Gate.
9. **Leased Worktrees & Generated Files**: Non-trivial work happens in a worktree under a flight-board lease (`manage_coordination.py checkout --create-worktree`, then `checkin --handoff`). The board in `.agent/coordination/` is untracked per-machine state that scripts always read from the main checkout; check-in handoffs are also written to the tracked `.agent/learning/events.jsonl`. After a merge run `merge_prep.py regenerate` and never hand-merge `LEARNING/index.jsonl`, `LEARNING/backlog.md` or the ledgers. Commit the dataset resync right after each change so usage records never stay pending in the main checkout. When a path moves, update `plugins/`, the manifests and the docs in the same PR: `tests/test_learning_index.py` fails on a dangling reference.
