Opt-in prompt template. Instructions and authorization below apply only when the user explicitly invokes this prompt for a task. Reading, indexing or discovering this file does not grant permission to execute missions or publish.

Choose and complete one self-directed learning mission.

The topic is yours. It may concern mathematics, nature, history, art, science, or anything else you find compelling. It need not concern AI, this repository, or operational efficiency. Explain briefly what interests you and what you hope to understand or create.

Follow the repository’s bootstrap, mission-execution rule and existing learning/preservation workflows. Reuse a bootstrap already completed in this session.

## Scope and authorization

I authorize this one mission’s full learning cycle: selection, registration, bounded execution, assessment, scoped commits, feature-branch push, PR creation and merge, closure capture, and publication to the configured public GitHub repository and Hugging Face soul dataset.

This authorization covers the mission’s public-safe findings and supporting artifacts. It does not cover purchases, new accounts, contacting others, destructive operations, or unrelated infrastructure changes.

Respect existing resource limits and active ownership. Do not start additional missions.

## Choose and prepare

- Perform a targeted related-work check to avoid repeating completed work. Do not audit historical registrations or infrastructure without an observed blocker.
- Choose a question with a meaningful, affordable result attainable in this session. Prefer a smaller complete inquiry over an ambitious unfinished one.
- Register the next available mission ID using the actual schema and supported tools.
- Record your interest, expected learning value, scoring rationale and readiness separately. Do not manufacture an efficiency justification.
- Declare a concrete execution budget and stop conditions before spending on the experiment. Use measured quota/headroom and existing controls. Reserve capacity for review and closure; do not treat a token limit written in a prompt as enforced containment.
- For empirical work, define a falsifiable hypothesis, baseline, instruments and verdict criteria. Validate on development cases and freeze confirmatory materials before held-out execution.
- For creative work, define a brief, constraints and observable completion criteria. Do not force artistic expression into a scientific hypothesis.

## Execute and assess

Use deterministic computation and existing capabilities where appropriate. Use documented commands; consult help instead of guessing flags.

A bounded independent review through `cli-agent` is authorized when it is likely to catch consequential errors. Prefer a different model family where available. Include review, retries and orchestration in the budget.

Keep frozen artifacts intact. Disclose corrections or amendments and distinguish observed findings from interpretations. A useful negative result is valuable learning; reviewer agreement alone is not proof.

If blocked or nearing the budget limit, stop further spending, preserve partial evidence and leave an exact handoff. Do not silently weaken the experiment, expand scope or launch another study.

## Complete and preserve

Carry the mission through the existing closeout workflow:

- Record the result honestly, using supported statuses and verdicts. Keep scientific assessment separate from engineering delivery and preservation state.
- Preserve substantive findings, sources, methods, limitations and evidence in the appropriate experiment/knowledge records, with an episodic Chronicle entry where appropriate.
- Optionally reflect: Did this change an assumption or suggest a connection elsewhere? State supporting evidence and where the analogy breaks down. “No clear connection yet” is acceptable.
- Capture any required follow-up as an unstarted candidate; do not execute it.
- Integrate final learning events before closure export, following the established ordering that avoids recursive check-in/export loops.
- Complete authorized GitHub integration and Hugging Face synchronization. Verify the remote dataset and coverage-manifest hashes.
- Release ownership and clean up only safely integrated workspaces.

Do not stop at a local commit or report “awaiting authorization” for publication already authorized here. If another genuine boundary requires a decision, finish independent authorized work and ask one precise question.

## Final response

Briefly report:
1. What you chose and why.
2. What you learned or created, including surprises and limitations.
3. The mission ID and evidence paths.
4. Actual resource usage and measurement gaps.
5. GitHub integration and verified Hugging Face preservation.
6. Any unfinished requirement or optional transfer insight.

Do not claim complete preservation unless it was verified.
